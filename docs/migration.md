# 实例迁移与多主机部署

Codex Remote 推荐采用“同一版本、独立实例”的部署方式。Linux 主机与 Mac mini 可以
同时运行，也可以在验证完成后切换入口；它们不共享运行中的 Worker 或可写数据库。

## 每台主机必须独立的内容

- `CODEX_REMOTE_TOKEN`、回环端口和 HTTPS/Tailscale 入口；
- `config/projects.json` 中与该主机实际目录对应的绝对路径；
- Codex CLI 安装、登录和权限配置；
- Remote 回收站文件、Worker SQLite、上传目录和 Unix socket；
- systemd unit 或 launchd label、环境文件和日志。

源码可从同一 Git commit 部署。若希望浏览器明确区分两台实例，建议使用不同主机名、
入口端口和令牌。项目 Git 仓库可以分别 clone/pull；不要用文件同步工具同时写两台机器
上的 `.git` 工作区、SQLite、附件目录或 Codex 会话目录。

## 推荐的低风险迁移

1. 保留原实例运行，在 Mac mini 安装相同 commit 的源码与依赖。
2. 在 Mac 上以最终服务用户独立安装并登录 Codex，复制或 clone 需要的项目仓库。
3. 新建 Mac 专属项目白名单、令牌、端口、状态路径和 Tailscale/HTTPS 入口。
4. 先前台验收，再按 [macOS 常驻部署](deployment-macos.md) 安装 LaunchDaemon。
5. 从另一台设备完成登录、普通消息、审批、停止、恢复会话和附件的真实验收。
6. 并行观察一段时间；确认新实例稳定后，才停止或保留原实例。

这种方式不迁移历史会话，但最容易回滚，也不会把旧主机的绝对路径和登录状态带入新机。

## 需要保留状态时

先决定要迁移哪些数据：项目 Git 历史通常通过远端仓库迁移；Codex 原生会话和登录由
Codex CLI 管理；Remote 状态只负责回收站、后台任务记录和附件。三者不是同一套数据。

如确需复制 Remote 状态：

1. 等待活动任务和队列清空，停止源实例的 Codex Remote 与上传服务；
2. 备份回收站文件、完整 Worker SQLite（包括可能存在的 `-wal`/`-shm`）以及整个上传
   根目录；
3. 复制到目标主机的独立目录，保持运行用户所有权、目录 `0700`、文件 `0600`；
4. 修改目标环境中的绝对路径，确认附件元数据所引用的路径仍然有效；
5. 在相同 Codex CLI/应用版本上启动并验证，再决定是否重新开放入口。

不要在服务运行时只复制 SQLite 主文件。跨主机复制 Codex 登录资料可能涉及凭证和版本
细节，默认应在新主机重新登录；若必须保留原生会话，应按所用 Codex CLI 版本另做受控、
可回滚的迁移，并验证会话中的 `cwd` 与新白名单一致。

## 分别部署与回滚

每台主机的服务管理、入口和数据目录都应能单独停止、升级和回滚。切换主入口之前保留
旧入口，可以最快回退；切换后应轮换不再使用的令牌。任何一台主机的卸载都不应删除或
修改另一台主机的数据，也不应依赖 `pkill codex` 一类全局命令。
