# 架构说明

Codex Remote 是单用户自托管的 PWA，用来在手机或电脑上控制主机上的 Codex CLI。
它解决的是高延迟下的手感问题：消息在浏览器本地编完再发，回复流式回来。

它不是通用终端，也不是把 Codex App Server 包一层直接开放——浏览器只看到为这个应用
设计的小协议。后端只监听 `127.0.0.1`，HTTPS 入口是独立的一层。

```text
浏览器 PWA → HTTPS 入口 → 127.0.0.1:<CODEX_REMOTE_PORT>
                              ├→ Unix socket 上的 ai-remote-upload（仅附件）
                              ├→ 一个共享的 codex app-server --stdio：会话列表与账号额度
                              └→ 每个活动会话一个 codex app-server --stdio 子进程
```

## 模块

| 目录 | 负责什么 |
| --- | --- |
| `src/server` | HTTP 与 WebSocket 入口、cookie 鉴权、Origin 校验、静态资源、项目锁、文件查看 |
| `src/app-server` | 与 Codex App Server 的 JSONL 通信、目录服务、工具展示 |
| `src/workers` | 每个会话一个 Worker：启动、排队、退出、状态持久化 |
| `src/sessions` | 会话列表、历史分页、归档与回收站 |
| `src/approvals` | 接收 App Server 的审批请求并转给浏览器 |
| `src/commands` | 斜杠命令目录与执行 |
| `src/projects` | 项目白名单解析 |
| `src/settings` | 后端全局应用设置（当前是附加 Developer 指令） |
| `src/shared-upload` | 独立项目 `ai-remote-upload` 的薄客户端 |
| `src/platform` | 平台差异（可用内存读取等） |
| `src/generated` | 由 Codex CLI 协议生成的类型，与具体 Codex 版本绑定 |
| `public/` | 前端 PWA：登录、项目与会话导航、应用设置、编辑发送、流式显示、Markdown、斜杠菜单 |

侧栏顶部的应用设置里，显示时区只保存在这台浏览器（默认上海，可跟随设备），
用来换算页面上的最后回复时间、用量重置时间和命令回执里的时间，不改变服务器时间戳。
附加 Developer 指令由后端写成 `settings.json`，同一 Codex Remote 后端上的已登录设备共用；
不同后端实例之间不同步。它在新建或重新载入会话时通过 App Server 的
`developerInstructions` 注入，不会改已经在运行的任务。

Codex 自己是原生会话和完整历史的权威存储。Node 这边额外保存已接受的消息、任务
状态、脱敏后的浏览器事件、权限模式、中断原因，以及会话附件显示索引，用来支撑
"关掉页面任务继续跑"，并把已知附件路径从页面副本里换成原名。

浏览器把未发送的正文和附件草稿按项目、会话隔离，并把草稿、尚未确认的消息发送和
`/rewind` 记录放在同一份本地恢复状态里。发送或回退只有在这份记录成功写入后才开始；
本地存储不可用时保留当前页面内容并明确拒绝操作，损坏数据也不会被当成空队列覆盖。
消息最终被后端拒绝时，正文和仍可辨认的附件会回到原会话草稿，不会覆盖当前打开的
另一个会话。显示时区和侧栏折叠仍是允许失败的外观偏好，不使用这套恢复承诺。

## 会话与任务

消息被接受后即可关闭页面，任务在独立 Worker 中继续，直到完成、被停止、遇到无人处理
的审批，或 Worker 失败。重新打开会话时，已完成的历史从 Codex 恢复，运行中的部分输出
从事件日志重放。

同一项目同时只允许一条未结束任务；另一条消息会立即被拒绝，不会进等待队列。任务控制权
属于登录会话而不是某条 WebSocket，任意在线设备都能看输出、处理全局待答区里的审批和
用户输入、停任务。待答区独立于当前时间线，切换或重画会话不会移除其他会话仍有效的请求。
默认最多同时两个 Worker；项目空闲但全局容量或内存不够时，那一条已接受的任务可以保持排队。
普通消息的停止覆盖排队、启动 Worker、等待 native turn ID 和已经运行这四个阶段。
压缩只在前两个阶段可以取消：压缩指令一旦发给 Codex 就不再接受停止，页面如实回绝——
中途打断一轮压缩会在会话上下文里留下什么，Codex 没有给出保证。
停止请求最多等待 Codex 确认 10 秒；超过期限仍没有回应，后端不再等这个 Worker，把任务
记为中断并强制关闭它，页面停止请求照常返回。离线处理和服务关闭用同一期限，一个不响应的
Worker 不会扣住其他会话。

Worker 的进程创建、App Server 初始化和会话恢复最多等待两分钟；超过期限仍未准备好，
后端会自动终止这个半成品进程，把任务记为启动失败并释放项目锁和 Worker 名额。这个期限
只监督启动，不限制正常对话运行时间，也不依赖用户点击停止。

服务关闭时，新建会话、恢复历史和短命令使用的临时 Worker 也由管理器统一关闭并等待收尾；
任务刚结束或空会话刚被回收、仍在关闭中的 Worker 同样要等到进程真正退出，管理器才算关闭完成。
关闭开始后不会再发布新的空会话，也不会让迟到操作越过状态库的关闭边界。
正在启动的任务如果还没向 Codex 提交这一轮，服务关闭会把它原样留在 `queued`，重启后
继续调度；已经提交的按后端停止（`backend_stopping`）记为中断，不会记成用户停止。

如果已接受的消息在 native turn ID 产生前失败，Codex 历史里还没有这一轮。后端会有界
保留该会话最后一次此类失败；重新打开时重放用户消息和失败原因，直到同一会话接受下一条
任务。已经产生 native turn 的任务仍以 Codex 历史为准，不另外保留一份终态事件历史。

浏览器重连时，如果任务已经接受但 Worker 还没恢复出可信历史，后端只报告 `queued` 或
`starting`，页面分别显示等待 Worker 或启动 Codex 的载入状态，并保留停止按钮。Worker
准备好后页面重新请求会话，再用 Codex 历史和当前任务事件绘制对话；后端不拿旧会话副本
填这个空档。

WebSocket 一旦关闭，后端立即撤销这台浏览器的在线登记和会话挂载，不等待连接上尚未完成
的业务请求。已经收到的请求可以在后台收尾，但迟到的恢复结果不能把死连接重新挂回会话；
没有成功挂载的新空 Worker 会在宽限期后自动回收。

会话可以搜索、归档、移入回收站、恢复；回收站满 30 天后连 Codex 侧一起删除。永久删除
会先把 `deleting` 阶段写进回收站状态，再依次删除 Codex thread、Worker 记录、附件显示
索引和钉住记录，最后才移除回收站条目。服务启动和每日清理都会续做遗留的 `deleting`
条目，所以进程在中间退出不会丢掉清理任务。运行中的会话不能归档或删除。

## 权限与审批

只支持"本次允许"和"拒绝"，不创建长期授权规则。所有待答卡都显示来源会话；命令审批
显示隐藏了路径和赋值内容的命令摘要，权限审批把网络与文件系统范围投影成不含宿主绝对
路径的说明。范围无法完整、安全展示时，页面只允许拒绝。任务终结、Worker 失败、Codex
收回请求或任一设备回答后，后端都会向所有在线页面广播同一个请求的终态。

最后一个客户端断开后保留 10 秒：普通权限下宽限期结束仍有审批等待，会先拒绝再中断
整轮；Full access 可以自动处理执行和文件权限，但选择题、验证码、登录授权这类必须人
回答的输入永不自动应答，无人在线时同样中断。宽限期结束时逐条处理，每条之前重新确认
还没有设备回来——处理一条要等一次中断往返，期间重连上来的设备应当接管剩下的审批。

## 斜杠命令

命令目录由后端下发，不写死在设备缓存里：`/compact`、`/model`、`/permissions`、
`/rename`、`/rewind`。输入框下方另有 `+` 菜单和模型、权限两个下拉入口；
`/model` 与 `/permissions` 由这两个下拉承担，不出现在斜杠菜单里。

`/model` 和 `/permissions` 只改当前会话的后续设置，不写 Codex 全局配置，任务运行期间
会被拒绝。

`/rewind` 回退用户确认时看到的指定 turn，不会在执行时重新选择“当前最后一轮”。浏览器
先把目标 turn ID、原消息和附件写入本地待确认记录；请求或随后重新载入历史时断线，重连
乃至重开 PWA 后仍用同一个 ID 确认。目标仍是最后一轮才执行回退；目标已经消失则视为此前
已成功，不再操作；目标仍存在但后面有了新轮次则拒绝回退。后端完成修改后只返回结果凭据，
页面再走正常的会话恢复链路载入历史，因此不会把破坏性修改和整段历史分页绑在同一次响应
里。

## 安全边界

- 只监听回环，入口挂掉也不会绑到公网网卡；App Server 从不绑定端口。
- WebSocket 升级前校验 Origin 和登录 cookie；令牌定时安全比较，换令牌立即失效全部 cookie。
- 每个白名单根和扫描出的项目都只有一个规范物理身份；恢复、排队、挂载和 Worker 提升
  始终核对项目 ID 与 Codex 返回的 `cwd`，同名项目只用公开 root ID 消歧。
- 浏览器拿不到主机绝对路径；系统抛出的带路径错误只写日志。
- 文件查看器只读白名单根目录内的 Markdown 和图片，不提供下载或目录浏览。
