# 架构说明

## 目标

Codex Remote 解决的是高 RTT 下的交互手感问题。编辑发生在浏览器本地，只有完整消息在点击发送后才进入网络；回复仍由后端接收流式增量，前端用小缓冲平滑显示。

它不是通用终端，也不是把 Codex App Server 包一层后直接开放。浏览器只看到为
单用户 PWA 设计的小协议。

## 组件

### 浏览器 PWA

浏览器负责：

- 保存访问令牌；
- 本地编辑消息；
- 选择项目和会话；
- 在响应式会话导航中搜索、归档、恢复和临时多选会话；
- 渲染最近的历史、流式回复、完成消息的 Markdown、命令状态和审批；
- 缓冲回复增量；
- 请求超时与断线重连；
- 启动状态保护和应用外壳缓存。

浏览器不会得到主机上的项目绝对路径。审批事件也不会包含原始命令、文件 Diff、thread/turn/item 内部标识。

错误提示同样受这条边界约束：仓库自己写的中文提示会原样发给浏览器，但操作系统
抛出的错误（例如项目根目录被删时的 `ENOENT`）只写进服务日志，浏览器只收到一句
通用说明；剩余文字里形似绝对路径的片段会被替换掉。

### Node.js 薄适配层

入口是 `src/server/main.ts`。它创建：

- `ProjectCatalog`：解析项目白名单；
- `AppServerClient`：管理一个 `codex app-server --stdio` 子进程；
- `CodexSessionService`：把项目 ID 翻译为 App Server 的 thread 请求；
- `ApprovalBroker`：接收 App Server 的双向审批请求并回答；
- `ProjectTaskLocks`：限制每个项目只有一个控制设备；
- `RemoteWebSocketServer`：提供静态 PWA、健康检查和浏览器 WebSocket。

这一层不保存 Codex 对话副本。会话仍由 Codex 自己保存和恢复。为了区分
“已归档”和“回收站”，Node 服务只额外保存一份小型回收站登记，其中包含
thread ID、项目 ID、删除时间和恢复目标，不包含标题、turn 或消息正文。打开
回收站列表时，显示摘要仍从 Codex App Server 读取。

### 前端启动与静态资源

`public/boot.js` 先于主模块运行。它在 `app.js` 完成初始化前禁用登录按钮，并阻止令牌表单退回浏览器原生 GET 提交；如果主模块迟迟没有就绪，登录框会直接显示启动错误。这样脚本加载失败不会表现成“令牌消失但没有提示”。

斜杠菜单是可选增强：`slash-menu.js` 单独注册菜单类，`app.js` 在它不可用时使用空实现，核心登录和会话选择仍能工作。当前浏览器请求等待 15 秒后会关闭连接并重连，避免一个没有响应的请求永久禁用页面控件。

HTTP 服务只提供 `src/server/http-server.ts` 中 `STATIC_FILES` 明确列出的文件。新增 `public/` 资源时，必须同时增加静态路由和相应测试，否则浏览器会收到 404。PWA 外壳资源使用查询参数版本，Service Worker 也使用独立缓存名；当前版本是 `v10`。修改外壳文件时要同步更新两处版本，防止旧 HTML 和新脚本混用。

### Codex App Server

后端通过子进程的 stdin/stdout 使用 JSONL。App Server 从未绑定公网端口，也不接受浏览器直连。

## 安全边界

### 网络边界

Node 服务固定监听 `127.0.0.1`，不区分私网版和公网版。部署者可以选择 Tailscale
Serve 提供 tailnet 内的 HTTPS，也可以选择 Caddy、Nginx 等公网 HTTPS 反向代理。
入口停止或配置失效时，Node 服务本身仍不会自动暴露到公网网卡。

WebSocket 不受浏览器同源策略保护，因此升级请求还会校验 `Origin`：只接受与
`Host`（或 `X-Forwarded-Host`）同源的来源，以及 `CODEX_REMOTE_ALLOWED_ORIGINS`
里显式列出的来源。不带 `Origin` 的非浏览器客户端（冒烟脚本、curl）仍然可用。
访问令牌仍是主要防线，这一层只是防止用户浏览的其它网站悄悄连上这个端口。
被拒绝的升级请求会在服务日志里写明 origin 和 host，便于换入口时排查。

### 项目白名单

`config/projects.json` 只允许配置项目根目录。后端扫描每个根目录的第一层普通文件夹，并给浏览器返回项目 ID 和名称。

浏览器发回项目 ID 后，后端重新扫描并解析真实路径。会话列表和恢复会话还会再次核对 Codex 返回的 `cwd`，防止跨项目恢复。

### 访问令牌

WebSocket 建立后必须在超时前提交至少 32 字符的令牌。比较使用定时安全比较。令牌保存在仓库外的环境文件中。

使用 Tailscale Serve 时，tailnet 身份和应用令牌形成两层保护。使用公网反向代理时，
网络身份层不再天然存在；可在代理前增加独立身份认证，但应用令牌仍必须保留。

### 审批

App Server 的内部审批对象仍保留原始命令，以便正确对应请求；后端发往浏览器时只挑选：

- 审批 ID；
- 类型；
- App Server 提供的文字理由；
- 时间；
- 网络目标（如有）。

原始命令、内部 thread/turn/item ID 不会进入浏览器协议。前端在没有理由时显示通用说明。

当前只支持“本次允许”和“拒绝”，不会创建长期授权规则。

## 会话与并发

电脑宽屏默认显示会话侧栏，用户收起后会在当前浏览器记住状态；收起时顶栏
不显示当前会话名称。手机使用默认关闭的抽屉。两种布局共用同一套搜索、分页、
归档、回收站和临时多选逻辑。

Codex App Server 的 `thread/archive` 和 `thread/unarchive` 表示普通归档。
移入回收站时，服务先确保 thread 已归档，再写入本地回收站登记；恢复时根据登记
回到普通列表或已归档列表。服务启动时和运行期间每天检查一次，登记满 30 天后
调用 `thread/delete`。如果服务在到期时没有运行，会在下次启动时补做清理。

浏览器的会话整理请求受项目锁保护，运行任务期间不能归档或删除。整理完成后，
所有已连接设备都会收到列表变更通知；停留在被移走会话上的设备会退出该会话。

同一项目同时只允许一个浏览器连接控制任务。另一个设备可以观察服务器推送的新增用户消息和 AI 输出，但不能同时开始或停止该任务。

登录或断线重连后只加载会话列表，不自动恢复浏览器上次保存的会话。恢复会话由用户明确选择，避免状态不确定的旧会话在启动阶段占住全部导航控件。

切换会话不会自动停止另一个设备控制的任务。控制设备断线时，后端会中断它拥有的活动任务；用户重新连接后可以明确要求继续。

这套锁只存在于当前 Node 进程内。服务重启后锁会重建，Codex 会话本身仍在磁盘上。

项目锁必须能自己放开，否则一个项目会永久停在“正在执行任务”。除了任务结束和
连接断开，还有两条兜底路径：关闭当前会话（切换、被归档或移入回收站）时立即
释放；`/compact` 这类响应里没有 turn ID 的命令，如果十秒内没有等到
`turn/started`，也会释放锁并通知浏览器结束“运行中”状态。

浏览器 WebSocket 有服务端心跳。手机换网络或息屏时 TCP 常常只是半开，没有心跳
就要等内核超时才会发现，这期间旧连接会一直占住项目锁，挡住用户重连后的新连接。

Codex App Server 会独占已加载会话的 rollout writer。官方的 `thread/unsubscribe`
在最后一个订阅者离开后仍会把 thread 保留最多 30 分钟，不能满足“关掉网页后立即
用本机 `codex resume` 接管”的需求。因此，只有在所有使用过 thread 的浏览器连接
都完成断线清理后，服务才会重建 app-server 子进程，立即释放 writer；HTTP 服务和
Tailscale/公网入口不会退出。仍有另一台设备连接时不会重建。恰好在重建期间到达的
浏览器请求会等新子进程完成初始化后继续。

## 斜杠命令

浏览器登录后从后端读取命令目录，所以命令名称和顺序不写死在每台设备的缓存里。当前按字母顺序提供：

- `/compact`：确认后压缩当前会话上下文；
- `/model`：从 App Server 实时模型列表中选择；
- `/permissions`：从当前项目允许的权限 profile 中选择；
- `/plan`：在普通模式和计划模式之间切换，可附带第一条计划问题；
- `/rename`：设置当前 thread 的显示名称；
- `/review`：检查工作区尚未提交的改动；
- `/rewind`：从当前会话的对话上下文移除最近一轮；
- `/status`：显示当前会话的模型、模式、权限和上下文用量；
- `/usage`：只读查看账户限额、每日、每周或累计 Token 用量。

`/model`、`/permissions` 和 `/plan` 通过 `thread/settings/update` 改当前已加载 thread 的后续设置，不写 Codex 全局配置文件。这三个命令在当前会话有任务运行时会被后端拒绝：它们会立刻影响正在跑的任务，而观察端设备本来就不该有任务控制权，否则它可以在别人的任务跑到一半时把沙箱放开到“完全访问”。Codex CLI 0.147.0 将会话设置、权限 profile 和协作模式接口标为实验 App Server 能力，因此客户端初始化声明 `experimentalApi: true`；这只开启 stdio 客户端协议能力，不会让 App Server 监听网络。

Codex Remote 不在 `thread/start` 或 `thread/resume` 上覆盖默认权限。新建和恢复会话
继承部署主机上的 Codex 默认配置；用户仍可通过 `/permissions` 切换 App Server
返回且允许使用的 profile。项目白名单负责 cwd 和会话归属，不等同于文件系统沙箱，
最终权限仍由服务账户权限与 Codex profile 共同决定。

`/model` 的模型和思考强度分两级选择。第二级只显示 `model/list` 为所选模型返回的 `supportedReasoningEfforts`；用户选定后再把 model 和 effort 一次性写入当前 thread。手动输入 `/model <id>` 仍使用该模型的默认 effort。

`/compact` 和 `/review` 会成为受项目锁约束的活动任务，可使用同一个“停止”按钮，控制设备断线时也会中断。第一版 `/usage` 不兑换 rate-limit reset credit，避免只读查看意外变成账户写操作。

`/rewind` 每次固定调用 `thread/rollback` 回退一个底层 turn；完成后用 App Server 返回的 turns 重建最近 20 轮和更早分页，所以再次执行会继续回退前一个 turn。浏览器历史快照会标记该 turn 是否包含可恢复的普通用户原文：回退普通对话后把原文放回输入框，回退 `/compact`、`/review` 等特殊 turn 后输入框保持空白。它只改变对话历史，不撤销该轮已经造成的文件改动。执行前必须确认，活动任务期间不能执行。

`thread/rollback` 在当前 App Server 中已经标记为 deprecated，因此调用集中在命令适配器里；接口被移除时需要替换实现，不能把它当作长期稳定协议。

## 历史与缓冲

恢复长会话时，后端只把最近 20 轮送进浏览器首屏，其余历史保留为分页来源，每次再加载 20 轮。这样减少浏览器 DOM 和渲染压力。

这不是 Codex 存储层分页：当前 App Server 恢复 thread 时仍可能把完整历史返回给后端。它主要优化后端到浏览器的传输与浏览器内存。

AI 文本仍是流式接收；前端按节奏合并增量后先以纯文本绘制，所以视觉上连续，但不会为每个极小片段都触发重排。等整条回复接收并显示完毕后，前端只做一次 Markdown 渲染。用户消息和恢复的历史消息本来就是完整文本，因此加载时直接渲染一次。

Markdown 是前端自带的简单子集：支持标题、段落、粗体、斜体、行内代码、列表、引用、代码块、链接、分隔线和管道表格，不做代码高亮。渲染器只创建固定的 DOM 节点，不执行原始 HTML；图片语法也不创建 `<img>`，只显示可点击的说明链接，避免浏览器自动请求外部图片。任务列表暂时按普通列表文字显示。

## 断线恢复

浏览器 WebSocket 断开后会重新连接并重新认证，但不会自动打开上次会话。用户从列表重新选择会话后，历史从 Codex 的持久会话恢复。

如果断开的是任务控制设备，后端按当前产品约定中断活动任务。重新连接不会擅自继续执行，需要用户再次发送“继续”等明确指令。

最后一个打开过会话的浏览器断开后，后台 app-server writer 会随子进程重建而释放，
随后可以从同一主机的 Codex CLI 恢复该会话。只浏览项目或会话列表、从未打开 thread
的连接不会触发不必要的子进程重建。

## 将来接 Claude Code

可以在同一个前端后面增加独立适配器，但不应把两套 SDK/App Server 混成一个协议实现。共享的应是浏览器会话外壳、项目选择、消息渲染和锁；Codex 与 Claude Code 各自保留后端适配层。

即使两者使用同一工作目录，也应继续由项目级锁禁止同时执行，避免两个代理并发修改相同文件。
