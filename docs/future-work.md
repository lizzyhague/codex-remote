# Future Work

这个文件只记录可能的修改方向。实际修改代码时，每次选择其中一项，重新确认需求、实现范围和验证方式；未选中的项目不自动实施。

## 1. Codex、Grok 与 Claude 共用的文件上传服务

### 目的

在手机使用 Codex Remote、Grok Remote 或以后实现的 Claude Remote 时，可以给当前
会话附上一张或多张截图或其他文件。上传、存储、过期清理和安全校验由一个独立的
模型无关服务负责；每个 Remote 仍独立部署，并按对应 AI 的协议把附件交给模型。

主要用途是偶尔发送两三张截图，让 AI 看懂界面、错误信息和布局并协助排查；它不是
网盘，也不建设完整的聊天附件管理系统。上传不是使用 Remote 的前置条件。

### 已确定的产品规则

- 浏览器只显示原始文件名和附件 ID，不显示或返回 VPS 绝对路径。
- 单文件上限为 **25 MiB**。
- 上传完成后默认保留 **30 天**，到期由共享服务自动清理。
- 不设置上传总数、每个会话累计数量或日常存储配额；一条消息可以附多张文件。
- 只保留磁盘安全门槛：可用空间低于配置阈值时暂停新上传，并给出明确错误，不影响
  已上传文件和正在运行的任务。
- 上传完成后只在输入区显示附件，不自动发送；用户仍需确认文字和附件后点击发送。
- 第一版以截图为重点，同时允许其他普通文件；无法被对应 AI 理解的格式应明确说明，
  不能假装读取成功。
- 当前预计只有 `codex`、`grok` 和 `claude` 三个调用方。接口保持模型无关，但不把它
  扩张成通用 AI 平台，也不合并三套 Remote 的运行时。

### 组件边界

```text
Codex / Grok / Claude PWA
        │  当前 Remote 的鉴权 + 一次性上传票据
        ▼
各自独立的 Remote 后端
        │  同源上传入口，流式转交
        ▼
仅本机可访问的共享上传服务
        │  存盘、元数据、限额、过期清理
        ├── Codex 适配器
        ├── Grok 适配器
        └── Claude 适配器
```

- 共享服务单独运行，只监听 Unix socket 或 `127.0.0.1`，不增加新的公网或 Tailscale
  浏览器入口。
- 浏览器仍只连接当前 AI 前端。Codex Remote、Grok Remote 和 Claude Remote 各自沿用
  自己的登录令牌、Origin 校验、项目白名单、会话状态和部署方式。
- 共享服务负责上传票据、字节流存储、文件元数据、生命周期和清理；它不启动 AI、
  不持有会话 Worker，也不理解 Codex、Grok 或 Claude 的消息协议。
- 每个 Remote 的薄适配层负责验证当前项目和会话、解析附件 ID，并把共享服务返回的
  本机文件交给对应 AI。

### 上传与发送流程

1. 用户在已选择项目和会话的输入区选择一个或多个本地文件。
2. 前端通过已经认证的 WebSocket 申请一次性上传票据，提交调用方、项目、会话、
   原始文件名、声明的 MIME 和预期字节数。
3. 当前 Remote 重新解析项目和会话，不接受浏览器提供的任意服务器路径；校验通过后，
   向共享服务申请短期、单次使用且绑定上述信息的票据。
4. 浏览器向当前 Remote 的同源 HTTP 上传入口发送原始字节流。Remote 将流转交共享
   服务，不把文件塞进 WebSocket JSON，也不先整体读入内存。
5. 共享服务写入临时 `.part` 文件，边接收边执行大小限制和哈希计算；完整接收后以
   原子重命名完成存盘，并返回附件 ID 和公开元数据。
6. 前端显示“文件名 + 附件 ID”的附件项。删除、上传失败或断线重试都不会自动发送
   对话消息。
7. 用户发送时，`message.send` 携带文字、`clientMessageId` 和附件 ID 列表。Remote
   再次验证附件属于当前调用方、项目和会话，且尚未过期。
8. 后端接受任务时固化附件 ID，并在任务完成或中断前为附件加保留锁，避免 30 天清理
   与后台 Worker 竞争。

### 存储与安全

- 上传根目录放在仓库之外，建议默认使用
  `~/.local/share/ai-remote/uploads/`，并允许通过环境变量覆盖；实施时必须分别验证
  Codex、Grok 和 Claude 对该目录的实际读取能力。
- 按调用方、项目和会话组织元数据；落盘文件名由服务器使用随机 ID 生成，只保留经过
  清理的扩展名。原始文件名仅作为显示元数据，不能参与路径拼接。
- 目录权限使用 `0700`，文件使用 `0600`，上传文件不设置可执行位。
- 不信任客户端文件名、MIME、扩展名、大小或路径；拒绝路径穿越、符号链接替换、
  超限字节、重复使用或过期票据。
- 共享服务使用 SQLite 保存附件 ID、调用方、项目、会话、原始文件名、实际路径、
  MIME、大小、哈希、状态、创建时间和过期时间。数据库与文件使用相同的敏感级别保护。
- 未完成的 `.part` 文件按较短时限清理；完成文件保留 30 天。服务启动后补做过期清理，
  运行期间定时清理，不要求 Remote 或浏览器持续在线。
- 第一版不做跨用户共享链接、公开下载地址、永久收藏、内容去重、缩略图图库或附件
  历史页面。

### 各 AI 的附件适配

#### Codex

- 图片优先使用 Codex App Server 的 `localImage` 输入。
- 其他文件使用本地文件 `mention`；必要时在文本中说明原始文件名和用途。
- VPS 路径只存在于后端到 App Server 的请求中，不返回浏览器。

#### Grok

- 先采用已有 HAPI 实践验证过的本地附件方式：把共享服务解析出的绝对路径以
  `@<path>` 写入发送给 `grok agent stdio` 的文本 prompt。
- 本机 Grok 1.0.5 的 ACP 初始化目前声明 `image: false`、`embeddedContext: true`。
  这只表示它没有正式声明 ACP 内联图片块，不表示 Grok 模型没有视觉能力，也不阻止
  CLI 解析本地图片引用。
- 实施时用真实截图验证 Grok 能否识别文字、颜色、控件位置和布局，而不只是确认文件
  存在。未经实测，不依赖未声明的 ACP `image` 内容块。
- 如果本地路径方式实测不能提供完整视觉理解，再接入用户已有的 OCR/视觉工具模型。
  OCR API key 只放服务器环境变量，不进入浏览器、仓库或附件数据库；识别结果可按
  附件 ID 缓存，避免同一图片重复计费。

#### Claude

- Claude Remote 实现时复用同一个附件 ID 和共享服务，不复制上传、存储与清理逻辑。
- 根据届时采用的 Claude CLI/API 实际协议，优先映射为原生图片或文件内容；不能假设
  它与 Codex 或 Grok 的输入格式相同。

### 验收方向

- 手机可以选择一张或多张截图；每张不超过 25 MiB，并看到文件名、附件 ID 和明确的
  上传状态。
- 上传完成不会自动发送；用户可以移除附件、补充文字后再发送。
- 浏览器协议、提示和日志中不出现上传根目录或文件的 VPS 绝对路径。
- Codex 能看懂真实截图，而不是只收到文件名；文本和其他支持文件也能被读取。
- Grok 的 `@<path>` 路径经过真实视觉测试；若失败，OCR/视觉模型降级路径能返回明确
  结果，而不是静默假装成功。
- Claude Remote 接入时只新增适配层，不复制共享上传服务。
- 同名上传、重复上传、超出 25 MiB、票据过期、上传中断、无权访问、磁盘低水位和
  服务重启都有明确、可测试的行为。
- 文件在保留期内不会被后台任务误删；满 30 天后确实清理，临时 `.part` 文件不会
  长期遗留。
