# Future Work

这个文件只记录可能的修改方向。实际修改代码时，每次选择其中一项，重新确认需求、实现范围和验证方式；未选中的项目不自动实施。

## 1. 简易文件上传

### 目的

在手机使用 Codex Remote 时，可以选择一张图片或一个文件上传到 VPS，再把文件在 VPS 上的绝对路径交给当前 AI 读取。

重点是解决临时发送截图或文件的问题，不建设完整的聊天附件系统。

### 期望交互

1. 用户在输入区选择一个本地文件。
2. Codex Remote 后端接收文件并保存到专用上传目录。
3. 后端返回文件在 VPS 上的绝对路径。
4. 前端把路径和简短说明填入当前输入框，由用户确认后再发送，例如：

   ```text
   我上传了一个文件，请读取：
   /上传目录/<会话标识>/<服务器生成的文件名>
   ```

5. AI 根据路径读取文本文件，或使用本地图片查看能力检查图片。

### 实现边界

- 不修改 Codex App Server 的消息协议。
- 不要求在聊天消息中显示图片、缩略图或附件卡片。
- 不生成公网文件链接；提供给 AI 的是 VPS 本地绝对路径。
- 不自动发送消息，上传完成后只填充输入框。
- 上传接口必须沿用 Codex Remote 现有鉴权。
- 服务器生成安全且不重复的文件名，不能直接信任客户端文件名或路径。
- 设置单文件大小限制，并明确上传失败时的反馈。
- 按会话隔离上传目录，避免不同会话的文件混在一起。
- 测试期间产生的临时进程、端口和文件必须当场清理，除非明确决定保留。

### 实现前待决定

- 上传根目录放在哪里，以及 Codex 的文件读取权限能否覆盖该目录。
- 文件保留多久：固定 TTL、会话删除时清理，或提供手动删除。
- 是否限制文件类型；图片、文本、PDF 和其他二进制文件分别如何提示。
- 自动填入输入框的文字格式。
- 同名文件、重复上传和上传中断如何处理。

### 验收方向

- 手机可以选择文件并成功上传。
- 上传后，输入框出现可读的 VPS 绝对路径，但不会自动发送。
- 当前 AI 能通过该路径读取支持的文本或图片。
- 无权访问、超出大小限制和上传失败都有明确提示。
- 约定的清理规则确实执行，不遗留无人管理的上传文件。

## 2. 后台执行与按需会话 Worker

> 实现状态（2026-08-24）：代码、单元测试、真实 App Server 恢复探针和隔离生产入口
> 冒烟检查已完成，常驻实例也已完成首次重启。手机断线测试确认 Worker 会在页面关闭
> 后继续，直到出现离线权限请求；同时暴露了 Full access 状态跨 Worker 丢失的问题。
> 持久化修复和完整测试已完成，尚待再次重启及手机验收。实现采用
> 后端稳定 `taskId`，原生 `turnId` 作为内部映射保存。

### 目的

用户发出消息并收到后端的接收确认后，可以立即关闭或离开前端页面。AI 的本轮执行由后端托管，不与页面或 WebSocket 连接的生命周期绑定。

每个正在执行的会话按需拥有独立 Worker。本轮回复完成且该会话的消息队列为空后，Worker 自动退出；下次发消息时，通过保存的原生 session/thread ID 恢复会话。只看会话列表不启动 Worker；打开历史会话时，为读取准确运行设置而启动的短生命周期 Worker 会在读取完成后立即退出。

### 期望交互

1. 前端提交消息，并等待后端返回 `accepted` 和稳定的后端 `taskId`。
2. 收到确认后，用户可以立即关闭页面，不必等待 AI 回复结束。
3. Worker 在后台继续执行，后端持续保存输出事件和本轮状态。
4. 用户重新打开页面时，可以继续查看流式输出，或直接读取已经完成的回复。
5. 本轮完成且消息队列为空后，Worker 自动退出。
6. 下次发送消息时，后端启动新 Worker，并恢复对应的原生会话。

### 权限与断线规则

- 后端以“是否至少有一个有效前端客户端连接”为准，而不是绑定某一个页面或设备；任意在线客户端都可以处理权限请求。
- 最后一个前端客户端断开后，保留 **10 秒宽限期**，避免切换 App、手机 NFC 刷卡、网络抖动或页面短暂重载造成误判。
- 普通或手动权限模式下：
  - 10 秒内重新连接时，继续正常展示和处理权限请求。
  - 宽限期结束后仍没有前端在线时，拒绝待处理的权限请求，并明确取消本轮执行，不能只拒绝单个工具后允许 AI 改用其他方式继续。
  - 保存已经产生的部分回复、权限请求摘要和中断原因，并把本轮标记为 `interrupted`。
- Full access 模式下，即使没有前端在线，也自动处理可授权的执行权限，让本轮继续到完成；本轮完成后仍按正常规则退出 Worker。
- Full access 不能替用户回答选择题、验证码、登录授权或其他必须由用户提供的信息。遇到这类交互且没有前端在线时，同样中止本轮。
- 终止 Worker 前，先向 CLI 返回拒绝并发送 abort/cancel，等待会话记录和原生 session/thread ID 刷新；超过合理超时后再终止整个进程树。
- 用户下次打开会话时，应明确看到上一次因无人处理权限或用户输入而中止，可以自行发送“继续”恢复工作。

### 状态与持久化

- 后端至少区分 `queued`、`running`、`waiting_for_permission`、`completed`、`interrupted` 和 `failed`。
- 前端断开不能删除或遗失已经接受的消息、部分回复、工具事件和最终回复。
- 每条客户端消息携带唯一 `clientMessageId`，避免网络中断后的重试造成重复执行。
- 输出事件具有可恢复的顺序标识；前端重新连接时可以从上次已接收的位置继续读取。
- 权限模式作为本轮的持久化配置保存，避免前端断开后因只依赖临时连接状态而产生歧义。

### 进程与并发边界

- 共享后端负责鉴权、连接、会话注册、持久化和 Worker 管理；不为每个会话复制一整套 HTTP 后端。
- 同一会话同时最多运行一个 Worker，多条消息按顺序排队，不能并发修改同一原生会话。
- Worker 必须拥有独立进程组，正常完成、用户取消或异常清理时都能终止完整进程树。
- 活动 Worker 数量需要设置明确上限；达到上限时向用户说明并拒绝或排队，不能静默终止其他会话。
- 启动 Worker 前检查系统可用内存，低于约定阈值时给出明确反馈，避免把 VPS 推入持续换页或 OOM。

### 本次采用的实现选择

- Codex 原生 thread ID 保存在任务记录中；真实探针已验证 Worker 完成后退出、由新
  App Server 进程恢复同一 thread 和 turn。
- Worker 在本轮完成且队列为空后立即退出，不保留复用窗口。
- 默认最多两个活动 Worker，启动前要求 Linux `MemAvailable` 至少 1024 MiB；超过
  Worker/项目限制的已接受消息保持 `queued`，不静默丢弃。
- 10 秒宽限期以全站已认证 WebSocket 数量判断，心跳负责清理半开连接。
- 后端重启后，`queued` 保留并继续调度；`running` 和
  `waiting_for_permission` 标记为 `interrupted`。
- 任务与事件写入 Node 24 自带 SQLite，数据库默认位于
  `~/.local/state/codex-remote/work.sqlite`。
- Full access 选择按 thread 写入同一 SQLite；任务接受时固化本轮权限模式，新 Worker
  必须先恢复到该状态，恢复失败时任务直接失败，不能静默降级到普通权限。
- Codex 空 thread 在第一轮前没有 rollout。新建空会话会暂时保留 Worker；首条消息
  后进入正常生命周期，所有查看页面离开后则在 10 秒后关闭。历史会话被明确打开时
  会用一个短生命周期 Worker 读取准确的运行设置，读取完成立即退出；只看会话列表
  不启动 Worker。

### 验收方向

- 消息收到 `accepted` 后立即关闭页面，AI 仍能完成回复并保存结果。
- 页面断开不会直接终止正在运行的 Worker。
- 普通权限模式下，无前端在线且 10 秒宽限期结束后，权限被拒绝、本轮被取消，并留下明确的中断记录。
- 10 秒内重新连接时，不会误拒绝正在等待的权限请求。
- Full access 模式下，前端断开后可授权的操作仍能继续，本轮完成后 Worker 正常退出。
- 重新打开页面可以恢复流式事件或读取完整结果，不重复执行已经接受的消息。
- 同一会话不会出现多个 Worker 并发执行，结束时不遗留子进程。
