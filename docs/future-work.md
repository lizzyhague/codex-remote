# Future Work

这个文件只记录尚未完成或尚未实测的修改方向。实际修改代码时，每次选择其中一项，
重新确认需求、实现范围和验证方式；未选中的项目不自动实施。

共享上传服务的接口、存储规则、Codex 现有适配，以及 Grok / Claude Remote 的接入边界
统一记录在[共享上传服务实现与接入说明](shared-upload-integration.md)中。

## 1. Codex 非图片附件实测

### 当前待确认

- 用真实 UTF-8 文本文件验证 Codex 不只是收到文件名，而是能准确理解附件内容。
- 验证文本附件内容不会出现在浏览器实时事件、重新加载后的历史或公开日志中。
- 验证多文本附件合计超过 512 KiB、无效 UTF-8、PDF 和其他当前不支持的二进制格式
  会在任务入队前得到明确错误，未发送的正文和附件草稿仍可恢复。
- 是否增加 PDF 或其他格式支持尚未决定；不能把“文件已经上传”当成 Codex 已经读取。

### 验收方向

- 上传一个带有可核对细节的文本文件后，Codex 能复述和分析文件中的实际内容。
- 浏览器只显示文件名、附件 ID 和公开元数据，不显示附件正文或 VPS 绝对路径。
- 不支持或超限的文件不会启动任务，错误说明与实际限制一致。

## 2. Grok Remote 接入

### 实现方向

- 复用现有共享上传服务、附件 ID、一次性票据、任务租约和清理逻辑，不在 Grok
  Remote 中复制存储服务。
- 先核对 Grok Remote 当时的真实鉴权、项目 ID、会话 ID、消息幂等和任务生命周期，
  再按接入说明增加票据申请、同源流式上传和附件租约。
- 根据届时实际使用的 Grok CLI / ACP 协议实现附件输入。可以先验证本地
  `@<path>` 引用，但不能因为 CLI 接受路径就声称模型具有视觉理解。
- 用真实截图检查文字、颜色、控件位置和布局。若本地路径不能提供完整视觉理解，再与
  用户讨论是否接入 OCR 或视觉模型降级；不自动实施替代方案。

### 验收方向

- Grok Remote 浏览器端可以上传、移除并随消息发送多个附件，且不会看到 VPS 路径。
- Grok 能回答截图中的可核对细节，而不只是确认文件存在。
- 不支持的格式和视觉能力不足都有明确反馈，不静默假装读取成功。

## 3. Claude Remote 接入

### 实现方向

- 复用现有共享上传服务和附件 ID，不复制上传、存储、租约与清理代码。
- 先确认 Claude Remote 实际采用的 CLI 或 API、鉴权、会话和后台任务模型，再设计薄
  适配层；不能假设它与 Codex 或 Grok 的输入格式相同。
- 优先映射为所用 Claude 协议的原生图片或文件输入。服务器路径只在 Remote 后端和
  coding agent 之间使用，不返回浏览器。

### 验收方向

- Claude Remote 只新增自身协议适配，现有共享服务无需复制或增加网络入口。
- 用真实图片和至少一种普通文件做内容级验证。
- 排队、运行、中断和失败期间正确维护附件租约，任务结束后释放。
